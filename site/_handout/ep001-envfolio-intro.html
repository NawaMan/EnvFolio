use them

folio exec

Your command directly gets the secrets. Never shown on screen or saved to a file.

▶ usage
folio exec [-s] <item>… -- <command>
each item → a variable, for that one command
gh/token → GH_TOKEN
/ becomes _, then UPPERCASE
EnvFolio
$# Use an item as a variable
$folio exec -s gh/token \
$-- sh -c 'echo ${GH_TOKEN}'
ghp_DEMO0000fake0000token
$# Or pick its name
$folio exec -s GITHUB_TOKEN=gh/token \
$-- sh -c 'echo ${GITHUB_TOKEN}'
ghp_DEMO0000fake0000token
$

-s|--secrets : include secrets in the injection.

EnvFolio

When needed, it converts the item into an environmental variable and inject directly to the command.

The conversion rule is just to change slash to underscore and uppercase the wholething.

So the command gets it directly -- not showing on screen or saved to file.

use several

A whole folder.

gh →
GH_TOKEN GH_USER
EnvFolio
$# Use every items in a folder
$folio exec -s gh \
$ -- sh -c 'env | grep GH_'
GH_TOKEN=ghp_DEMO0000fake0000token
GH_USER=demo@example.com
$
$# See which is which, dryrun
$folio exec --names -s gh \
$ -- gh repo list
GH_TOKEN <- 🔑gh/token
GH_USER <- 📄gh/user
$
  • A folder brings every item under it
  • --names shows where each variable comes from — nothing is read, nothing runs

EnvFolio

EnvFolio is one bash script so there is nothing to hide -- look at the code.

It needs only a few standard dependencies like pass, gpg, and git.

Is secret store is readable by `pass` so you can always fall back to that.

It also has built-in backup and restore feature so you don't loose your items.
