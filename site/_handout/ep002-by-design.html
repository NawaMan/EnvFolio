Folio

This new software offers to handle your sensitive information.

So being suspicious about it is a fair reaction.

In this video, I will discuss how Folio is designed and built to be:

  • trusted,
  • secure,
  • portable, and
  • easy to use.
trusted · 1 / 4

Built on GPG

GPG holds your key, locked with your passphrase. gpg-agent remembers it for a while.

Folio

How can a new tool be trusted?

Well, it leans heavily on existing trusted tools, such as GPG and pass.

Folio does not do any cryptographic operations by itself: it delegates all of those to GPG and pass.

The keys used are all GPG keys managed by the GPG key ring and agent.

trusted · 2 / 4

Secrets in pass

pass keeps the secrets encrypted to your key, and git keeps every change.

Folio

The secret store is managed by `pass`, another trusted, standard Unix tool.

So we get the same file and folder structure, and the encryption is done by `pass`.

In fact, if you stop using Folio, the existing secrets in the store can be read by just using `pass`.

trusted · 3 / 4

Texts are signed

gpg signs each one with your key. A text changed behind Folio's back is refused.

Folio

Plain text items stay plain, and they are stored in the same folder structure as the secrets.

That is, they follow the `pass` structure.

Additionally, Folio uses GPG to sign the text value to ensure its integrity.

trusted · 4 / 4

One readable script

One bash file, plain text, start to end.

Folio
$pushd "$(dirname "$(which folio)")"
~/.local/bin ~
$version=$(folio version | cut -d" " -f2)
$releases=https://github.com/NawaMan/\
$EnvFolio/releases/download
$curl -fsSL $releases/v$version/SHA256SUMS \
$ | sha256sum -c
folio: OK
$popd
~
$
  • plain text: every line to read
  • your folio = the release's hash
  • flat, linear: nothing hidden
  • or ask an AI: does a secret leave?
Folio

To further the trustworthiness, Folio is implemented as one single bash script.

It might be long, but it can be read from top to bottom.

You can ask an AI to read it for you, and check if the handling of secrets is proper and secure.

Also, with a very limited list of dependencies, such as GPG, pass and git, there is no place to hide any misbehavior.

secure

Direct to process

The command gets texts and secrets directly, as variables.

Folio
$folio exec -s gh -- release.sh
==| Releasing v1.2.0 |==
GH_USER : demo@example.com
GH_TOKEN: ✅ given
Publishing ...
...
--| Done |--
$
  • convert item to variable, automatically: gh/token → GH_TOKEN
  • direct to the sub process;
    • no need to show on screen
    • save it to a file
    • nor copy to clipboard
  • nothing to clean up: no variable left, no file to delete
  • nothing in your shell history
Folio

Second, being secure.

Folio exec turns each item into a variable, and hands it directly to the command.

No need to show it to you, to save it to a file, or to copy it to the clipboard.

Nothing to clean up afterward. Nothing in your shell history.

portable

Take it with you

💻 your laptop
$folio export -s --vars app2.vars \
$ -o app2.folio
✓ Items: 3 (texts: 1, secrets: 2)
✓ File: app2.folio
$
↓ app2.folio · one locked file
☁️ a server, or a cloud booth · no store
$folio exec -s --from app2.folio \
$ --vars app2.vars -- deploy.sh
==| Super Cool App -- Deployment |==
...
--| Deploying is completed |--
$
  • locked: a passphrase, or their public key
  • store's key never leaves your machine
  • import it, or use the file as the store
Folio

Third, portable.

Folio `export` puts just what you need into one locked file.

A new key will be created specifically for that locked file.

Your local store's key stays there; it never leaves the computer.

Then you can import it somewhere else, or use the file directly as the store, on any remote machine you need.

usable · 1 / 4

Name it your way

Name environmental variables the way you want.

Auto naming

From the path.

gh/token→GH_TOKEN gh/api-key→GH_API_KEY gh/api+key→none, with a warning

Explicit naming

$ folio exec -s \
    GITHUB_TOKEN=gh/token \
    -- gh release list

Namespace

A top @namespace is dropped.

@group/gh/token→GH_TOKEN
Folio

Last, usability. Folio comes with many conveniences.

For example, each item becomes a variable named from its path, or you can pick the name yourself.

usable · 2 / 4

A vars file

List what a command needs, by its own names. No value inside.

Folio
$folio check vars deploy.vars
$folio exec -s --vars deploy.vars \
$ -- ./deploy.sh
$
deploy.vars · commit it with the code
GITHUB_TOKEN=@{gh/token}
AUTH=Bearer @{gh/token}
REGION=@{aws/region:-${AWS_REGION}}@{aws/*}
@{name}
an item from the store
${NAME}
an environmental variable from the running shell
:-
a fallback, when the item is not there
Folio

A vars file lists what a project needs, with no value in it, so you can commit it with the code.

usable · 4 / 4

Three ways to unlock

How often you type the passphrase is up to you.

defaultasked once, then a while
pinentry
gpg-agent remembers it · the default
autonever asked
FOLIO_STORE_PASSPHRASE_FILE
a file only you can read · a machine you trust
strictasked every time
--fresh-passphrase
forgotten when each command ends · a machine you trust less
Folio

And you choose how often to type your passphrase: once in a while by default, never on a machine you fully trust, or every time on one you don't.
